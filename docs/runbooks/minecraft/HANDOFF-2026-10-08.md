## The stuck-bot bug (fixed, root cause known)

Symptom: a bot standing at a wall or a one-block step is pulled back by the
server ~20x/s and never moves on; breaking the block frees it.

Root cause (measured with raw position packets from a test account):
**Paper 26.2 rejects a movement whose bounding box touches a block face
exactly (gap 0.0). A gap of 1e-6 is accepted.** Mineflayer's collision always
ends exactly flush, so every move into a wall was rejected.

Fix: `app/physicsfix.js` patches `AABB.computeOffsetX/Z` of prismarine-physics
so every horizontal collision stops `GAP = 1e-4` short. Verified live: 670
corrections in 140 s before, 0 in eight round trips over the hills at
`-104 71 -7` and `-112 66 -2` -> `-106 75 -22` after.

Dead ends, do not repeat: widening `playerHalfWidth` (prismarine-physics lets a
box that already overlaps a wall walk straight through it, and server resets put
the bot 1e-4 into the wall); sending `hasHorizontalCollision`; the axis-order
patch (`wip/crafting` commit `6fefedf` is obsolete); a plugin cancelling moves
(no evidence; the failure reproduces with raw packets). `unwedge()` in
`bots.js` stays as a last-resort safety net.

Untested: ceilings (vertical flush against a block above the head). Only X/Z are
patched. Test with raw packets before touching Y.

## The hub

Lab app = hub; a laptop (or any tailnet machine) runs bots as a *worker*.

- Worker: `nix run .#mcbots-worker -- bot5` (`worker.nix` wrapper sets
  `HUB_URL=wss://bandit-lab.tail7facc9.ts.net:8446/worker`,
  `HUB_TOKEN_FILE=/run/secrets/mcbots-worker-token`, `MC_HOST=100.125.161.81`).
  Entry `app/worker.js`, client `app/hubclient.js` (`HubClient`, `RemoteWorld`).
- Hub: `app/hub.js` (`Hub`, `RemoteRunner`, `createWorkerServer`). Second
  listener `WORKER_PORT` (8096 in the container, published on `127.0.0.1` only)
  serving nothing but the WebSocket upgrade on `/worker`; everything else 404.
  `server.js` wires it in when `WORKER_TOKEN` is set; remote bots live in the same
  `runners` Map as the lab's, so `/api/state`, `/api/debug` and the dashboard
  show them with `host`, `remote`, `connected`, `lastSeen`.
- Auth: `Authorization: Bearer <token>` (sha256 + `timingSafeEqual`), 20 failed
  attempts / minute then 429. Token = sops secret `mcbots-worker-token`; lab
  hands it to the container via `/run/mcbots/seed.env` (`mcbots-seed` unit), never
  the plain environment; laptop declares it in `nixos/secrets-workstation.nix`.
- Protocol v1, JSON text frames, max 256 KB. Worker -> hub: `hello {v, host, bots}`,
  `status {bots:[snapshot+debug]}` (1/s), `observe {mobs, blocks, gone}`,
  `claim {id, key, by}`, `release`, `ping`. Hub -> worker: `welcome {protectedAreas,
  supplyChest}`, `error`, `job {bot, type, args, replace}`, `world {players,
  mobs, blocks, claims, bluemap}` (1/s), `claim_result {id, ok}`, `pong`.
- Limits: 8 bots per worker, 16 remote bots total, 8 claims per bot, hello within
  5 s, heartbeat 10 s, silent for 30 s = dropped. Claims expire after 120 s and
  are released at once when the worker leaves. A reconnect replaces the old
  connection for the same names. Worker back-off 1 s .. 30 s.
- Reservations: the hub's `WorldModel` is the only table (`claim`, `release`,
  `releaseAll`). `collect()` in `bots.js` asks `await world.claim(...)` per
  candidate block; on a worker that is one round trip (3 s timeout = refused).
  If the hub is unreachable `world.unreachable` is true and digging jobs fail
  with `hub unreachable: not digging without block reservations` (fail closed).
- Everything a worker sends is sanitised (`cleanSnapshot`, `cleanDebug`) and a
  worker may only act for the names in its hello, never for the lab's
  `BOT_NAMES`.
- Rotation: set `mcbots-worker-token` in both sops files again, deploy the lab,
  `sudo systemctl restart mcbots-seed docker-mcbots`, `nrs` on the laptop.
- Troubleshooting: see `BOTS.md` ("Hub: bots on other machines").

## Shipping to the lab (there is no `ship-claude` yet)

A push to `main` deploys to bandit-lab within about an hour
(`lab-update-apply.timer`; only signed fast-forwards are applied). Procedure that
worked today, always in a clean worktree so the dirty tree cannot leak in:

```bash
cd ~/src/bandit-nix
git fetch origin main <branch>
git worktree add --detach /tmp/shipN origin/main
cd /tmp/shipN
git cherry-pick -S <sha> ...                    # re-sign as the owner
git log --show-signature -1 | grep -E "^commit|Good signature|BAD"
nix build ".#nixosConfigurations.bandit-lab.config.system.build.toplevel" --no-link --no-update-lock-file
git push origin HEAD:main                       # THIS DEPLOYS; the owner runs it
cd ~/src/bandit-nix && git worktree remove /tmp/shipN
```

Deploys that restart `docker-minecraft` disconnect players; mcbots-only changes
do not. After a deploy, if the old image still runs:
`sudo systemctl restart docker-mcbots`; first publication of a new Serve port
needs `sudo systemctl restart mcbots-https`.
